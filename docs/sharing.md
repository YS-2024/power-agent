# 多用户外网访问

个人空间继续在本机 `http://127.0.0.1:8000/` 使用原资料和历史，无需登录。外网入口使用独立账号系统，与个人空间隔离；不将本机已有聊天或记忆发布到外网。

## 管理员开始使用

1. 确认个人应用及 PostgreSQL 已启动，运行 `powershell -ExecutionPolicy Bypass -File start-share.ps1`。
2. 访问地址保存在 `data/sharing/access.md`。首次升级会生成 `admin` 账号，初始密码仅写入 `data/sharing/admin-access.md`，请勿将此文件发给普通用户。
3. 管理员登录后点击「账号管理」，创建每位用户的独立账号和初始密码，选择普通用户或管理员，以及是否允许阅读公共资料。将各自凭据单独交给本人。
4. 用户可点击「修改密码」。管理员可以重置密码、禁用/启用账号和调整公共资料阅读权；修改后旧登录状态失效。禁用不删除数据。
5. 运行 `stop-share.ps1` 结束分享。再次启动默认复用原账号、密码和数据，只有临时网址改变；`-Resume` 仍兼容。电脑重启后若旧进程已退出，启动脚本会恢复原空间。

## 隔离与资料权限

| 内容 | 普通用户 | 管理员 |
| --- | --- | --- |
| 自己的聊天、图片、长期记忆、报告 | 读写 | 读写自己的 |
| 别人的私有数据 | 不可访问 | 页面/API 也不可访问 |
| 自己上传的个人资料 | 读写、检索 | 读写自己的 |
| 公共资料 | 有阅读授权时可读取、检索，不可增删 | 上传、阅读、检索、删除 |
| 账号管理 | 不可访问，可修改自己的密码 | 创建、禁用、重置密码、调整公共阅读权 |

导入默认为「我的资料」；管理员可切换到「公共资料」。同一问题只会检索当前账号的个人资料及获准阅读的公共资料，引用编号在合并后重新生成。报告文件按账号分别保存。跨用户传入会话、记忆、报告或私有资料 ID 不会得到其他用户的数据。

外网公共资料首次来自本机资料库快照，后续各自修改不会自动同步。本次从 guest 升级时保留旧演示资料作为公共库；旧共享聊天、记忆和报告留在原演示 schema/目录归档，不分配给任何新账号。旧 guest 密码不可用于新多用户入口。

## 实现与边界

账号元数据与公共资料位于现有 demo_<随机ID> schema；每位用户的私有资料、向量、聊天及记忆位于服务端根据账号 ID 确定的 account_<账号ID> schema。请求不能自行指定 schema。服务器数据库账号可管理这些 schema，这属于应用层隔离，不是为每位用户创建独立数据库登录；本机数据库管理员仍可管理数据。

密码只以独立盐的 PBKDF2-HMAC-SHA256（600000 次迭代）摘要入库，不以明文保存；初始管理员凭据文件属于本机引导文件，改密后不再有效。8 小时会话使用 HttpOnly、SameSite=Strict Cookie，公网 HTTPS 附加 Secure。每次请求复核账号启用状态和凭据版本；CSRF 令牌按会话生成。同一浏览器换账号后旧页面请求会要求刷新，前端会话选择按账号分别保存。最多 100 个账号。

账号由管理员创建，不开放自助注册；尚未提供邮件找回、双因素认证、每人独立 API 密钥或计费额度。模型调用仍使用服务器配置的统一 API。账号禁用或权限修改会阻止新请求，已经授权并开始执行的请求不强制撤回。私人数据默认仅本人通过应用访问，不能将公共库当作保密资料存储位置。

服务仅监听本机 8001 端口，Cloudflare Quick Tunnel 提供临时 HTTPS 地址，不开放数据库或防火墙端口。需保持电脑联网不休眠。日志保存在 data/sharing/<随机ID>/，不记录密码或请求正文。

[Cloudflare 官方下载](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/downloads/)；[Quick Tunnel 说明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)：临时域名、停止即断开、不保证持续可用，不适合长期生产部署。当前客户端为已验证摘要的 cloudflared 2026.10.0，放置于 data/tools/cloudflared.exe。

# 电知 · 电力知识 Agent

一个可在本机运行的中文电力知识助手，支持知识问答、资料检索和报告导出。基于 LangChain + LangGraph 开发，使用 PostgreSQL + pgvector 保存资料并进行语义与关键词混合检索。

## 启动

菜单中的 `8` 可关闭本项目的本机服务（默认端口 8000），外网分享和数据库继续运行。正在运行本机服务的窗口若无法输入菜单，可再次双击 **启动服务.bat**，在新窗口选择 `8`。未完成的请求会中断，已保存的数据保留。也可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\stop-local.ps1`（自定义端口加 `-Port 端口号`）。脚本会核对监听进程、项目 Python 路径和启动命令，无法确认归属时拒绝关闭。

Windows 下可直接双击项目根目录的 **启动服务.bat**：选择 `1` 启动数据库和本机服务，保持窗口打开，然后访问 http://127.0.0.1:8000/ 。需要外网分享时，再次双击该文件并选择 `2`，菜单会等待并直接显示公网登录链接。选择 `3` 关闭外网分享；本机服务在其启动窗口按 Ctrl+C 关闭。选择 `4` / `5` 用默认浏览器打开本机空间 / 公网登录页，`6` 在记事本查看管理员初始账号信息，`7` 刷新服务状态与链接。公网用户使用管理员分配的独立账号密码；管理员登录后通过“账号管理”创建用户和设置资料库权限。菜单仅在本机分享及隧道进程运行时显示当前地址，不保证外网网络连通。退出菜单不会关闭后台分享，账号和历史数据会保留。此入口复用下面的 PowerShell 脚本，首次安装仍需完成依赖与配置。

需要 Python 3.10 或更新版本（当前已用 Python 3.13 验证）。首次安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

配置 `.env` 中的数据库连接与向量模型后启动。本机已配置 WSL 数据库，建议使用 `powershell -ExecutionPolicy Bypass -File .\start.ps1` 同时启动数据库和应用。其他机器的 Docker 部署、迁移和备份步骤见 [数据库说明](docs/postgres.md)。

数据库已运行时，可单独启动应用：

```powershell
.\.venv\Scripts\python.exe app.py
```

浏览器打开 http://127.0.0.1:8000 。端口占用时加 `--port 8001`。也可运行 `powershell -ExecutionPolicy Bypass -File .\start.ps1`（可选 `-Port 8001`）。在 PyCharm 中将项目解释器设为 `.venv\Scripts\python.exe`，再运行 `app.py`。按 Ctrl+C 停止服务。

## 功能

- **知识问答**：中文术语扩展与 PostgreSQL 全文检索 + pgvector 语义检索 → RRF 合并 → 原文摘录或模型综合 → 文件与行号引用。
- **智能助手**：默认入口，可自然聊天、专业答疑和连续追问；模型结合资料目录与上下文决定是否检索，再组织解释和引用。无相关资料时仍可给通用回答，并明确依据范围。
- **图文聊天**：在智能助手中上传、粘贴或拖入图片，识别图片文字、解释图表、描述设备外观和比较多张图片，支持带历史图片的连续追问。
- **资料库**：导入 UTF-8 的 TXT / Markdown（单份 1 MB）和 PDF / DOCX（单份 10 MB）；提取文本后分块、向量化存入 PostgreSQL，支持去重、查看文本、检索和删除。最多 100 份，单份提取文本最多 1 MB。
- **文档引用**：PDF 保留物理页码（从 1 开始，最多 200 页），DOCX 保留正文段落号和表格行号；问答与报告同时附上位置及提取文本行号。DOCX 段落号按正文段落顺序计数，不是 Word 页码。仅保存提取文本，不保存原文件。PDF 扫描页、图片、DOCX 文本框、页眉页脚、嵌套表格不在解析范围；扫描件请先 OCR，混合 PDF 会提示未提取到文字的页。
- **研究报告**：输入主题，保存并下载 Markdown 报告，包含研究正文、引用、资料范围与核验事项。
- **故障回退**：向量服务失败时明确提示并使用 PostgreSQL 关键词检索；生成模型失败或引用无效时返回原文摘录。新资料导入需要向量服务，数据库不可用时不会自动切换旧资料库。
- **模型可选**：接入兼容 Chat Completions JSON 协议的本地或云端模型服务。

内置 3 份中文教学摘要，涉及功率与电能、功率因数、电气安全资料边界；各文件均附官方原始发布页面。内置资料是概念示例，不构成中国现行规范库。正式使用请导入有权使用的教材、设备文档和有效规程文本。

## 配置模型

### 302.AI / gpt-4o-mini

当前接入使用 [302.AI Chat 接口文档](https://302ai.apifox.cn/api-147522039) 的非流式 Chat Completions 协议。密钥仅放在本机 `.env`，该文件已加入 `.gitignore`。

```dotenv
LLM_API_URL=https://api.302.ai/v1/chat/completions
LLM_MODEL=gpt-4o-mini
LLM_API_KEY=在此填写自己的密钥
LLM_MAX_TOKENS=2000
LLM_TEMPERATURE=0.2
```

后端以 `Authorization: Bearer …` 发送鉴权，不经浏览器传递密钥。`LLM_MAX_TOKENS` 限制输出长度，`LLM_TEMPERATURE` 控制随机性。请求超时为 45 秒，不自动重试以避免重复计费。401、402、403、404、429、服务异常、超时和无效引用会显示对应提示并回退本地摘录；被截断的模型回答也会回退，避免把不完整结果当成完整报告。

启动 `.\.venv\Scripts\python.exe app.py` 后，页面显示“模型已配置 · gpt-4o-mini”。该标签只表示配置已加载；单次回答下方的“由 302.AI · gpt-4o-mini 生成”才表示本次模型调用成功。

可单独运行 `.\.venv\Scripts\python.exe check_model.py` 验证连接。该命令会发起一次真实的计费请求，只发送脚本内置的短测试资料，不读取个人知识库，不打印密钥或服务商原始错误响应。普通单元测试不会访问付费 API。

智能助手没有相关依据时可给通用解释，不编造知识库引用；“资料研读”和研究报告仍严格依据知识库，找不到依据时提示补充资料。

### 其他兼容服务

将 `.env.example` 复制为 `.env`，填写 `LLM_API_URL`（完整 Chat Completions 接口地址或 `/v1` 基础地址）、`LLM_MODEL`、`LLM_API_KEY`，然后重启。已有环境变量优先于 `.env`。

模型接口需要接受 `model`、`messages`、`stream` 字段，并返回 `choices[0].message.content`。可使用本机 HTTP 地址，外部服务必须使用 HTTPS；不自动跟随重定向。模型请求通过 LangChain `ChatOpenAI` 发送，兼容服务也需接受 `max_completion_tokens` 输出长度参数。没有在本项目内安装、下载或启动任何大模型。

**数据流**：文档保存在配置的 PostgreSQL 中。导入时，文档标题及分块正文会发往 302.AI 向量接口；检索时，问题也会向量化。生成回答时，问题及命中的片段发送到聊天模型。向量化和聊天分别计入服务商用量，密钥只由后端读取。

## 使用示例

智能助手：直接输入消息或选择开场话题，Enter 发送（Ctrl+Enter 也支持），Shift+Enter 换行；中文输入法选字期间不会误发。最近最多 10 轮、20000 字符的上下文与滚动会话摘要用于连续追问。对话和图片保存在 PostgreSQL，刷新和服务重启后可恢复。历史会话每次加载 10 轮，可加载更早消息；新建对话保留旧会话，删除会话会移除它的消息、图片及由它自动生成的记忆。最多 100 个会话，每个最多 500 轮、100 MB 图片。

长期记忆：默认启用，自动从当前用户原话摘取明确的偏好、职业背景、学习目标或项目背景，跨会话可用。点击“长期记忆”可新增、编辑、删除或清空，最多 50 条、每条 300 字。关闭“使用并更新记忆”后，本轮不读取或新增长期记忆，当前会话上下文仍在。删除记忆不会删除历史聊天；需要一并清除上下文时删除相应会话。自动提取可能遗漏或需要纠正，不能保证永久记住每个细节。

精确核对聊天记录：问“我第一个问题是什么”“我的第二条消息是什么”或“上一条消息是什么”，会直接读取当前会话的原始用户消息，不依赖模型猜测，也不检索电力资料。首条消息超出最近 10 轮、服务重启或关闭长期记忆后仍可核对。按用户消息顺序计数（图片消息也计入）；不跨会话查找。普通概括式回顾仍使用近期上下文和摘要。

发送后立即清空输入框和待发送图片；发送失败会恢复原草稿和附件。生成期间显示“停止生成”按钮，可结束本轮并继续发新消息。已取消的轮次不保存聊天、摘要或长期记忆；若回复已先完成保存，则保留完整回复。停止是结束本轮，不支持从中断位置续写。程序会关闭本轮模型/向量请求连接，但服务商已执行的计算和费用不一定能撤回。

图片：点击“添加图片”、向输入框粘贴截图或把图片拖入聊天输入区域。每条最多 4 张，可只发送图片不输入文字。支持 PNG、JPEG、WebP、GIF；原图每张最多 10 MiB、4000 万像素。浏览器解码后自动缩至最长边 2048 像素，重新编码为 PNG 或 JPEG（每张最多 2 MiB），透明区域铺白，GIF 只分析首帧，去除原始元数据。小字可能因缩图变模糊，识别读数时可先裁剪相关区域。

图片和文字经本地后端以 `content: [{type: "text", ...}, {type: "image_url", image_url: {url: "data:image/...;base64,...", detail: "auto"}}]` 发给模型。最近上下文最多包含 8 张图片且图片数据 URL 总长度不超过 1600 万字符，超过限制不向模型发送较早图片。新附件保留，失败不会清空附件或改变已成功的聊天上下文。图片随会话保存到数据库，不自动加入文档知识库；会随保留的上下文再次发送给模型并计入服务商用量。

能力范围参考 [GPT-4o mini 官方文档](https://developers.openai.com/api/docs/models/gpt-4o-mini)：文字和图片输入，文字输出。本项目没有为该模型添加原生语音、视频或图片生成能力；图片理解不等于精确仪器读数或现场安全判断。

数据流：规划模型收到用户消息、近期文字上下文、首条用户消息、摘要、启用的记忆和资料标题目录；回答模型收到相关资料片段、近期对话及图片、首条用户消息、摘要和启用的记忆。内部参考数据与真实用户发言分开。通常每轮 2 次模型调用；精确核对记录不调用模型，身份问答跳过规划调用；检索另调用向量接口，引用或概念修正最多增加 1 次模型调用。正文、图片和密钥不写入请求日志，LangSmith 上传关闭。本机个人入口保留原工作空间；外网按账号隔离对话、记忆、报告和个人资料，可授权共享公共资料。不提供实时联网搜索。

1. 在智能助手问“kW 和 kWh 有什么区别？”，再追问“举个例子”，查看自然解释与资料引用。
2. 在资料库导入自己的 `.txt` / `.md` / `.pdf` / `.docx` 文件，然后搜索设备名称或术语。PDF / DOCX 会显示解析和索引进度；错误及缺页提示保留在导入区域。
3. 在研究报告页输入“功率与电能的基础概念学习报告”，点击生成并下载。

离线回答和报告是检索摘录，不会假装完成模型推理。模型回答是草稿；引用编号验证只保证编号存在，不证明每一项陈述都由引用支持。

## 框架架构

LangChain 负责 `ChatOpenAI` 模型调用以及 `BaseRetriever` / `Document` 检索接口；LangGraph `StateGraph` 执行智能助手、资料研读和报告工作流。智能助手通过模型路由按需检索并保存成功轮次；资料研读与报告失败时可回退到原文摘录。详见 [架构说明](docs/architecture.md)。

当前为受控工作流：智能助手的模型决定是否进入检索节点，程序限制可执行操作；不执行任意代码或联网工具。主库使用 PostgreSQL + pgvector；会话、摘要、记忆与成功回复一起事务提交，失败不留下半轮对话，request_id 支持幂等重试。持久化使用应用数据库表，不依赖进程内 MemorySaver，也不是 LangGraph 节点级断点续跑。

## 当前边界

个人入口仅监听 `127.0.0.1`；外网入口现支持独立账号、个人数据隔离和公共资料权限，暂不提供生产部署配置。支持中文关键词和向量混合检索、PDF / DOCX 文字提取；尚未集成联网实时资料抓取或 OCR。首次内置资料只载入一次。

知识助手用于资料辅助学习与研究，不直接控制设备。现场作业、保护整定或标准适用性需由相应专业人员对照原始有效文件核验。

## 临时外网分享

运行 `start-share.ps1` 启动独立账号入口，链接在 `data/sharing/access.md`，管理员初始凭据在 `data/sharing/admin-access.md`。管理员通过「账号管理」创建用户、重置密码和分配公共资料阅读权。用户的聊天、记忆、报告和个人资料互相隔离；再次启动保留账号及数据。运行 `stop-share.ps1` 结束分享。详见 [分享说明](docs/sharing.md)。
